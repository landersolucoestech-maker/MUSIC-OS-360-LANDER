NOME: MUSIC OS 360
TIPO: ERP Musical SaaS Multi-tenant

QUEM USA O SISTEMA:
  · Gravadoras (independentes e majors)
  · Produtoras musicais
  · Editoras musicais (publishing/direitos autorais)

QUEM NÃO USA O SISTEMA:
  · Distribuidoras NÃO são tenants/utilizadores
  · Distribuidoras (DistroKid, TuneCore, ONErpm, Believe, CD Baby) são
    ALVOS DE INTEGRAÇÃO — o sistema envia lançamentos para elas via API,
    eliminando o login manual em cada plataforma.

FUNÇÃO DA DISTRIBUIÇÃO NO SISTEMA:
  Simplificação de fluxo de trabalho: a gravadora/produtora/editora
  distribui os lançamentos musicais de DENTRO do MUSIC OS 360, sem
  precisar fazer login em cada distribuidora separadamente.
  A distribuidora recebe os metadados e assets via API.

MODELO DE NEGÓCIO:
  · SaaS com planos mensais via Stripe (Starter / Professional / Enterprise)
  · Multi-tenant: cada cliente é um tenant isolado com org_id próprio
  · Whitelabel opcional para grandes clientes
  · Billing em BRL (Brasil)

BUG #3 — RBAC completamente inactivo — MOCK_TENANT com owner sempre (CRÍTICO)
──────────────────────────────────────────────────────────────────────────────
FICHEIRO: client/src/app/providers/TenantContext.tsx
LINHA:    136-146

CÓDIGO ACTUAL (errado):
  const MOCK_TENANT: Tenant = {
    ...
    permissions: ROLE_PERMISSIONS.owner,   // ← SEMPRE owner, independente do role
  };

PROBLEMA: RequirePermission chama hasPermission() que verifica as permissions
do tenant. Se permissions = ROLE_PERMISSIONS.owner, hasPermission() retorna
true PARA QUALQUER MÓDULO E QUALQUER ACÇÃO. O RBAC está inactivo.

CÓDIGO CORRECTO:
```typescript
// Em TenantContext.tsx, na função que inicializa o tenant:
// ANTES de chamar setTenant, ler o role do JWT e usar as permissões correctas:

import { jwtDecode } from "jwt-decode";

function getPermissionsFromToken(): TenantPermissions {
  try {
    const token = localStorage.getItem("access_token");
    if (!token) return ROLE_PERMISSIONS.viewer;
    const decoded = jwtDecode<{ role: TenantRole }>(token);
    return ROLE_PERMISSIONS[decoded.role] ?? ROLE_PERMISSIONS.viewer;
  } catch {
    return ROLE_PERMISSIONS.viewer;
  }
}

const MOCK_TENANT: Tenant = {
  id:    "mock-org-001",
  name:  "Gravadora Demo",
  slug:  "gravadora-demo",
  role:  "owner",
  // Derivar permissions do role real, não hardcodar owner:
  permissions: ROLE_PERMISSIONS.owner,  // manter para mock
  ...
};
```

BUG #4 — Dois sistemas RBAC incompatíveis coexistindo (ESTRUTURAL)
────────────────────────────────────────────────────────────────────

SISTEMA A — TenantContext (5 roles):
  FICHEIRO: client/src/app/providers/TenantContext.tsx linha 13
  type TenantRole = "owner" | "admin" | "manager" | "editor" | "viewer"
  Usado por: RequirePermission.tsx → hasPermission()

SISTEMA B — useHasRole (12 roles):
  FICHEIRO: client/src/shared/hooks/useHasRole.ts linhas 6-36
  type AppRole = "super_admin" | "tenant_owner" | "admin" | "financeiro" |
                 "juridico" | "artista" | ...12 roles totais
  Usado por: SuperAdminGuard.tsx, useCanAccess.ts, AdminRoute.tsx

PROBLEMA: Os dois sistemas têm tipos diferentes, hierarquias diferentes,
e não comunicam entre si. Um utilizador pode passar pelo Sistema A mas
falhar no Sistema B (ou vice-versa).

SOLUÇÃO:
  · Sistema A (TenantContext) = roles INTERNOS ao tenant (o que o utilizador
    pode fazer DENTRO da organização). Manter como está.
  · Sistema B (useHasRole/AppRole) = roles GLOBAIS da plataforma (super_admin,
    tenant_owner). Manter separado.
  · NUNCA usar Sistema B para controlar acesso a funcionalidades de tenant.
  · SuperAdminGuard usa Sistema B para /admin/* — correcto.
  · RequirePermission usa Sistema A para módulos de negócio — correcto.
  · Não misturar os dois.

type TenantRole = "owner" | "admin" | "manager" | "editor" | "viewer"

PERMISSÕES POR MÓDULO (PERMISSION_MATRIX completo):
──────────────────────────────────────────────────
Módulos controlados: catalog, contracts, accounting, artists, crm,
                     marketing, rh, settings, admin, audit

Actions disponíveis: read, write, delete, export

  owner:   TUDO em todos os módulos (billing, exclusão, super config)
  admin:   TUDO exceto billing management
  manager: TUDO exceto audit (read-only) e settings (read-only)
  editor:  read + write + export em todos (sem delete, sem audit, sem settings)
  viewer:  read-only em todos (sem audit, sem settings)

```typescript
// server/src/modules/websocket/ws.gateway.ts
@WebSocketGateway({ cors: { origin: process.env.FRONTEND_URL } })
export class WsGateway {
  @WebSocketServer() server: Server;

  // Emitir evento para todos os clientes do mesmo tenant:
  emitToOrg(orgId: string, event: string, data: unknown) {
    this.server.to(`org:${orgId}`).emit(event, data);
  }

  // No handleConnection: validar JWT + join room
  async handleConnection(client: Socket) {
    const token = client.handshake.auth.token;
    const payload = this.jwtService.verify(token);
    client.join(`org:${payload.org_id}`);
    client.data.org_id = payload.org_id;
    client.data.user_id = payload.sub;
  }
}
```
