```txt id="2v0z4l"
Realize uma LIMPEZA TÉCNICA PROFUNDA no projeto antes de qualquer nova refatoração estrutural.

O objetivo é eliminar completamente resíduos, código morto, duplicidades, arquivos órfãos, imports inválidos, estruturas antigas e qualquer elemento que esteja causando conflito arquitetural, inconsistência, acoplamento desnecessário ou degradação de manutenção.

IMPORTANTE:
NÃO criar novas funcionalidades.
NÃO alterar regras de negócio ativas.
NÃO refatorar domínio ainda.
NÃO reorganizar arquitetura ainda.
Primeiro execute SOMENTE a limpeza técnica segura e validação estrutural.

# OBJETIVO

Executar uma varredura completa no projeto para:

- remover código morto;
- eliminar resíduos antigos;
- limpar imports;
- remover componentes abandonados;
- excluir arquivos sem uso;
- remover rotas órfãs;
- eliminar dependências obsoletas;
- limpar estrutura;
- reduzir conflitos internos;
- estabilizar a base do sistema.

# EXECUTE AS ETAPAS ABAIXO

# 1. IDENTIFICAR E REMOVER ARQUIVOS ÓRFÃOS

Localizar e remover:

- arquivos sem importação;
- componentes nunca utilizados;
- hooks sem consumo;
- services abandonados;
- contexts sem uso;
- pages inacessíveis;
- modais antigos;
- views não utilizadas;
- adapters mortos;
- stores sem consumo;
- helpers abandonados;
- usecases sem integração;
- arquivos vazios;
- placeholders antigos;
- arquivos duplicados;
- versões antigas coexistindo.

VALIDAR antes da exclusão:
- imports dinâmicos;
- lazy loading;
- rotas;
- providers;
- consumo indireto.

NÃO remover nada ativo.

# 2. LIMPAR IMPORTS E EXPORTS

Remover:

- imports mortos;
- exports não utilizados;
- aliases inválidos;
- dependências circulares;
- referências quebradas;
- imports duplicados;
- código comentado antigo;
- variáveis sem uso;
- funções mortas.

Executar correção automática quando possível.

# 3. ELIMINAR RESÍDUOS DE REFATORAÇÕES ANTIGAS

Identificar estruturas híbridas:

- componentes antigos coexistindo com novos;
- modais substituídos mas ainda existentes;
- páginas antigas;
- services duplicados;
- hooks redundantes;
- contexts substituídos;
- stores legadas;
- wrappers abandonados;
- versões antigas de layout;
- providers antigos.

Remover apenas o que estiver realmente obsoleto.

# 4. LIMPEZA DE ESTRUTURA

Remover completamente:

- dist
- build
- .local
- cache
- artefatos temporários
- arquivos gerados
- logs
- resíduos de compilação

Garantir que:
- source fique limpo;
- gitignore esteja correto;
- build artifacts não estejam versionados.

# 5. VALIDAR DEPENDÊNCIAS

Executar auditoria completa:

- depcheck
- ts-prune
- eslint unused imports
- unused exports

Identificar:
- libs não utilizadas;
- dependências parcialmente abandonadas;
- versões incompatíveis;
- pacotes duplicados;
- dependências mortas.

Remover SOMENTE o que não possuir uso real.

# 6. VALIDAR ROTAS E NAVEGAÇÃO

Identificar:

- rotas órfãs;
- páginas inacessíveis;
- lazy imports quebrados;
- links inválidos;
- breadcrumbs mortos;
- tabs sem destino;
- menus apontando para páginas removidas.

Corrigir vínculos quebrados.

# 7. VALIDAR MODAIS E COMPONENTES

Identificar:

- modais duplicados;
- views antigas;
- componentes substituídos;
- componentes nunca renderizados;
- wrappers abandonados;
- componentes experimentais esquecidos.

Remover apenas os obsoletos.

# 8. VALIDAR HOOKS, SERVICES E CONTEXTS

Localizar:

- hooks sem consumo;
- services placeholders;
- contexts nunca utilizados;
- providers mortos;
- adapters sem integração.

Remover apenas se realmente não houver vínculo ativo.

# 9. VALIDAR ESTRUTURA SHARED

A pasta shared deve conter apenas:
- componentes reutilizáveis reais;
- utilitários ativos;
- contratos compartilhados;
- tipos compartilhados.

Remover:
- componentes abandonados;
- abstrações prematuras;
- widgets antigos;
- componentes específicos de domínio que foram colocados em shared incorretamente.

# 10. GARANTIR ESTABILIDADE

Após toda limpeza:

- validar build;
- validar tipagem TypeScript;
- validar imports;
- validar rotas;
- validar providers;
- validar módulos ativos;
- validar navegação;
- validar renderização;
- validar lazy loading.

NENHUMA funcionalidade ativa deve quebrar.

# RESULTADO FINAL ESPERADO

O projeto deve terminar com:

- estrutura limpa;
- sem arquivos mortos;
- sem imports inválidos;
- sem código abandonado;
- sem resíduos de refatorações antigas;
- sem duplicidade estrutural;
- sem componentes órfãos;
- sem dependências inúteis;
- sem build artifacts;
- sem rotas quebradas;
- sem providers mortos;
- sem conflitos internos;
- sem acoplamentos desnecessários;
- base estabilizada para futura refatoração arquitetural.

IMPORTANTE:
A limpeza deve ser SEGURA.
Priorize estabilidade e integridade estrutural.
NÃO remover nada que tenha vínculo funcional ativo.
```
