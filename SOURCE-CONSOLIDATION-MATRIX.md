# Source Consolidation Matrix — v2.0.0

The design rule is one authoritative owner per concern. External tools may optimize transport/context, but they cannot become hidden policy, memory, task or completion authorities.

| Source / mechanism | Retained strength | v2 integration | Explicitly excluded / constrained |
|---|---|---|---|
| Previous MUSIC OS 360 v1.2.1 pack | project-specific specialists, hash baselines, scope safety, native Claude hooks, adversarial/regression review, bounded memory, proxy launchers | refactored into L0–L5 impact/risk, structured evidence, requirements closure, side-effect ledger, hash-chained journal, semantic validator, dynamic graph and expanded specialist registry | free-form PASS evidence, fixed T-tier governance, fixed component counts, prose-only requirement closure |
| Claude Code native runtime | project agents, Tasks, hooks, permissions, sandbox, status lines, worktrees/Agent Teams | orchestration substrate and tool lifecycle; current hook names/PreToolUse decision semantics are used directly | custom emulation of native task/subagent lifecycle; Agent Teams as default scheduler |
| OmniRoute | provider routing, health/fallback/circuit behavior | optional routing adapter only; memory disabled, compression disabled in full stack | governance, task ownership, policy, evidence, project memory |
| Headroom | context/schema optimization | optional context adapter only | routing authority, durable memory, policy, autonomous learning |
| Claude-Mem concepts | persistent high-value recall + progressive disclosure | native project ledger with source hash/fingerprint staleness | background autonomous observer/peer coordinator |
| Task Observer concepts | repeated-failure and improvement signals | one staged improvement queue + failure fingerprints | active-delivery policy self-modification |
| Claude Code Setup concepts | launch/prime/status ergonomics | project-local launchers, doctor, Skills, status surfaces | global wrapper/config takeover |
| Software supply-chain practices | artifact identity, provenance, SBOM/signing concepts | versioned policy + specialist + release contracts; adapters can be added for project CI | pretending local prompts provide cryptographic attestation |

## Conflict ownership

- **Policy/authority:** Constitution + policy/runtime only.
- **Task/execution topology:** Claude native Tasks plus compact canonical mirror in `ops/state.json`.
- **Evidence:** structured EvidenceRecords; no router/memory/reviewer claim can directly mark completion.
- **Memory:** native bounded ledger only.
- **Context optimization:** Headroom only when stack mode is intentionally selected.
- **Provider routing/fallback:** OmniRoute only when routed mode is intentionally selected.
- **Completion:** deterministic gate engine + Stop completion gate; durable external CI/branch/deploy controls remain authoritative at production boundaries.
